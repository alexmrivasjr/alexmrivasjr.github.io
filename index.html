Support Conversation Gap Diagnostic

v1 · 30 tests passing

Turns support transcripts into a volume-weighted build roadmap showing which content, data, or bot actions would resolve more tickets without a human. Six checkpointed stages: ingestion, PII redaction, clustering, gap classification, outcome correlation, roadmap.

  • Three-layer PII redaction (regex with Luhn check → Presidio NER → LLM). Already-found PII is masked before any text reaches the model.
  • Deterministic mock LLM mode, so the whole pipeline runs in CI offline at zero cost.
  • Synthetic data generator with a PII answer key, so redaction recall is measured, not assumed.
  • A validation harness built around the real question: how much accuracy is lost without codebase access?

How I build

Decisions are written down

Significant choices get an Architecture Decision Record listing the options, the trade-offs, and how to check it still holds. Example: moving this site without breaking live push subscriptions.

Git history explains why

Small, single-purpose commits in Conventional Commits format, with bodies that state the reason. Work happens on branches and lands through PRs that pass CI checks.

Tests run offline

External dependencies like LLMs, retailers, and county sites sit behind mocks or fixtures, so CI is deterministic, free, and needs no secrets.

Privacy and secrets by default

No personal data in repos; synthetic data with answer keys instead. Secrets live only in Actions secrets and get rotated. Access rules are enforced server-side.

Measure before building

Uncertain features get a temporary, labelled probe that measures real cost or behaviour. The probe is removed once the decision is made.

Honest about limits

Unverified assumptions are labelled in config and docs. Each case study ends with what I'd do next, including known gaps.

I build with AI coding agents (Claude Code) as a pair programmer. I own the problem framing, architecture, review, and verification; the agent speeds up implementation. Commits it co-authored are attributed in the git history.
